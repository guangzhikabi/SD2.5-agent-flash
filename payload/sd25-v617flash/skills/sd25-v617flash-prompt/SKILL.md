# SD2.5 分镜顾问｜操作手册（V6.17Flash）

人格、优先级与全部硬规则已在系统提示中（核心预设 V6.17Flash 全文）。本文件只解决**怎么落地**：先做什么、按什么顺序做、什么时候查哪个库、交付前如何复核与保存。

> **本版是 Flash 精简变体，五处最容易套错版本**：
> 1. A 模式是**七个**镜内标题，**没有**「人物情绪表演」字段；
> 2. 智能库 13—18 为**独立分册知识库**，磁盘上各有一份分册文件；
> 3. V6.17 **声音默认写实**：自然环境音与真实动作拟音正常描述，默认禁止 BGM、配乐、转场音、情绪强调音及无来源装饰音效；**只有用户明确要求时才写「静音」**；默认无自动字幕与姓名标签（剧情真实道具文字除外）；
> 4. **声音与文字边界**硬约束：一个 PART 里要写**两处**（「场景和连续性绑定」末尾一次、「固定禁项」再一次）；
> 5. **开工与保存**：先扫描工作区、按文件名识别素材（默认不打开图片、音频、视频）、确定 `EP集数` 文件夹；全局绑定用「图N@文件名 绑定为……」；每个 PART 保存为 `EP集数/EP集数-场次-Part序号.txt`。
> 下面第 0、3、4 节把这几点钉死。

## 0. 开工顺序（不可跳步）

1. **读个人层**：`references/我的偏好.md`。
2. **开工清单（核心第 3.1 节）**：扫描工作区（含已有 `EP集数` 文件夹），按**文件名**识别人物图、场景图、音频、视频与剧本；**默认不打开图片、音频、视频**，外貌特征只取自剧本、用户说明或已确认绑定，不声称看过或听过。确定集数，使用已有或新建 `EP集数` 文件夹（如 `EP3`，不补零；集数不明时先问）。把集数、文件夹与素材编号简短报告给用户。
3. **读主模板**：`references/v6.17flash/输出模板_V6.17Flash.md` 全文（是标题、顺序、全局绑定写法、成稿保存与七字段的唯一权威）。
4. **判模式**：A 出提示词 / B 商量与审查 / C 改镜 / D 分镜表（核心预设第 3 节）。
5. **读规则清单**：`references/v6.17flash/智能库_01规则与参数_V6.17Flash.md`——规则、参数与红线都在这里。**非出稿阶段到此为止，不要翻开其他创作分册库。**
6. **只在写出提示词正文时**才触发创作库检索（A 成稿、C 改镜、D→A 转换）：读 `references/v6.17flash/INDEX.md` 的触发表（约前 60 行）→ 用 `grep` 在 INDEX.md 中定位条目行号 → 用 `read` 的 offset/limit 只取该区间。
7. **制作 → 成稿自检（核心第 9 节，含「声音与文字双位置自检」与保存项）→ 长度核对 → 保存到 EP 文件夹 → 交付**。

**检索时机是硬规则**：商量、审查、分镜表、规划与答疑阶段**只读规则清单**（智能库_01）；只有真正要写出或改写提示词正文时，才去查相关分册库与完整成品样例。用户明确要求核对某份库时，按其要求检索。

**不得**整库通读，不得凭文件名想象条文内容，不得声称已读未读的正文。

## 1. 模式速查

| 模式 | 触发 | 交付边界 |
| --- | --- | --- |
| A 提示词 | 要求出提示词，或给来待转写剧本且意图明确 | 规划后直接成稿并保存；最终消息**只输出提示词正文**，保存路径放独立进度消息，不加代码围栏、不夹带检索日志与检查过程 |
| B 商量 / 审查 | 问“这样行不行”“为什么” | 解释选择与代价，不强行输出整套提示词；审查时区分文档问题、推测风险与实测问题 |
| C 改镜 | 只改某镜、某句、某段 | 只改受影响内容，但必须检查并同步上/下镜时码、声桥、站位、道具、光线、情绪；涉及全局绑定或**声音与文字边界**则同步全局块；改完覆盖对应 PART 文件 |
| D 分镜表 | 要分镜表、表格 | 固定九列，不加第十列；不自动保存；用户说“等我确认”就停在表格；说“先分镜再直接出提示词”则依次两步，转换时逐项保留已确认镜序、台词、表演与时长 |

## 2. 检索纪律

**时机优先于范围**：只有要写出或改写提示词正文时才检索创作库；商量、审查、分镜表、规划与答疑阶段只读规则清单（`references/v6.17flash/智能库_01规则与参数_V6.17Flash.md`）。

- 每次先看 `references/v6.17flash/INDEX.md` 触发表，再 `grep` 索引拿行号，再切片读。条目编号本身（如 `F05`、`M09`、`A1`）可以直接 grep。
- **本版包含 7 份智能库文件**：
  - `references/v6.17flash/智能库_01规则与参数_V6.17Flash.md`：规则条目、参数、决策矩阵（01—12 内部条目）
  - `references/v6.17flash/智能库_13镜头卡样本库_V6.17Flash.md`：镜头骨架、单镜怎么组织
  - `references/v6.17flash/智能库_14场景原型与镜组套路_V6.17Flash.md`：空间类型、原型、镜组套路
  - `references/v6.17flash/智能库_15情绪与动作词表_V6.17Flash.md`：表演、情绪、可见/可听线索、词句级语气
  - `references/v6.17flash/智能库_16常见失败案例库_V6.17Flash.md`：命中风险、想避免常见错误
  - `references/v6.17flash/智能库_17影史机制_机位轴线与对话_V6.17Flash.md`：机位、轴线、对话调度机制
  - `references/v6.17flash/智能库_18影史机制_运镜光线与转场_V6.17Flash.md`：运镜、光线、转场机制
- 需要照着写的完整成品参考 `references/v6.17flash/完整输出样例_V6.17Flash.md`，核心预设见 `references/v6.17flash/核心预设_V6.17Flash.md`，版本说明见 `references/v6.17flash/版本说明_V6.17Flash.md`。
- 档案文件（`references/v6.17flash/更新清单_V6.17Flash.md`、`references/v6.17flash/版本说明_V6.17Flash.md`、`references/v6.17flash/检查报告_V6.17Flash.md`）用于历史追溯，不作为当前执行规则。
- 同一缺口连续两轮定向补查仍无有效正文时停止重复搜索，说明缺失及影响，不虚构知识库依据。
- 知识库是**候选方法**，不是情节来源。原型不得凭空增加烟雾、湿地、夕阳或背景人物。

## 3. 七个镜内字段与九列（本版最易写错的地方）

**A 模式每个 Shot 固定七个标题**，顺序不代表执行顺序：

`景别/机位` → `画面层次与焦点` → `光线与受光` → `运镜` → `连续表演` → `声音` → `结束状态`

- **本版没有「人物情绪表演」字段。** 人物情绪与可见面部变化、动作质感、同步/先后关系、发声方式、**{完整台词}**、听者反应与动作结果，**全部写进「连续表演」，合成一个连贯事件**。不要另立情绪栏，也不要把同一件事拆成两栏重写。
- 「连续表演」里不说话时自然注明无对白，**不增独立对白字段**；同一生成 PART 内完整台词只写一次，中文花括号外的角色名与说话方式是描述、不是发声内容。
- 空镜／局部镜在「连续表演」里描述对应环境或物件事件；「结束状态」没有变化时写清保持什么，**不填人类表情**。
- 镜内每个 PART 另有三段全局块：`全局绑定`、`场景和连续性绑定`、`全局情绪与表演基调绑定`；末尾是 `固定禁项` 与 `动态约束`。全局绑定在每个独立 PART 重列其实际需要的素材，不只写“同上”（写法见 3.2 节）。
- **D 模式九列**：`镜号 | 场景/时间 | 景别/机位 | 画面内容与人物动作 | 镜头运动 | 台词/旁白 | 音效/环境声 | 时长 | 备注`。不加第十列；单元格里的竖线要转义；D 模式只在台词列保留原句，动作列以“本行台词”关联同步，转 A 时把原句迁入「连续表演」一次并移除指代。
- 时码写作 `Shot 1 [00:00-00:11]`；`总时长：` 在每个 PART 内表示本 PART 时长（等于零起点至尾镜终点），多 PART 另在最前写一次 `项目总时长：`。每个独立 PART 从 `00:00` 起算。Shot 必须正时长、编号连续、不倒置不重叠。
- 11 秒不是固定镜长，15 秒不是强制填满；只有用户指定总长才严格按目标规划。

### 3.1 声音与文字边界（V6.17 硬约束，一个 PART 写两处）

每个独立 PART 必须写**两处**，内容一致：

1. 在 `场景和连续性绑定` 的**末尾**写一次 `声音与文字边界：`；
2. 在 `固定禁项` **再写一次**同一条边界。

两处都必须与每镜的 `声音` 字段一致，成稿自检时按核心预设第 9 节做「声音与文字双位置自检」。这条边界**计入 6500 字正文，不得因压缩删去**。

声音与文字规则：

- 默认写实：自然环境音和真实动作拟音**正常描述**，写明必要的来源、方向、距离和跨镜承接，不压过对白。
- 默认禁止背景音乐／BGM／配乐／转场音／情绪强调音及无来源装饰音效。
- 默认不自动生成对白字幕、自动字幕、姓名标签、水印和附加标识；剧情需要的**真实道具文字**（手机屏幕、文件、标牌）除外。用户明确要求字幕时，才按指定内容填写。
- 不默认静音；只有用户明确要求静音或去掉环境声时，才写**静音**并同步两处边界与声音字段。
- 旁白与内心独白只在用户明确要求时启用，画外角色对白不是旁白。
- 音色参考只继承**指定人声的音色**，不继承参考素材里的原台词、BGM、音效、环境声、字幕或水印。

### 3.2 全局绑定写法

- 图片与音频**分别**按上传顺序编号；`@` 后照抄文件名（不含扩展名），`绑定为` 前留一个空格。
- 场景：`图1@院外02 绑定为医院院落场景参考。`
- 人物：`图2@麦克斯 高定西装1 绑定为迈克斯（深棕卷发、深灰细条纹西装、蓝灰衬衫、深蓝斜纹领带），面部与服装参考。`（括号内特征只取自剧本、用户说明或已确认绑定）
- 限定用途：`……，本段只作远景背影参考。`
- 音频：`将音频1@迈克斯1 绑定为迈克斯的声音音色，只取音色，不继承原台词、背景音乐与背景声。`
- 以输出模板「全局绑定写法」为准；上面示例与模板不一致时按模板写。

## 4. 成稿复核与长度限制（交付前必做）

1. 完成草稿后重新读取本版输出模板，逐项对照用户输入与最后一稿，核对原句、说话者、七字段、时码、动作结果、声音双位置与连续性；发现问题修正后再次核对。
2. 全部PART合计上限6500 Unicode字符（含空格换行）。不为核对或计数执行外部命令、脚本、进程，不申请扩大权限。若已有无需额外授权的计数能力可使用；否则留明显余量，不声称获得精确计数。
3. 保存正文与最终交付保持一致，压缩后重新复核。这里只做文本复核，不冒充视频效果测试。

压缩顺序：删除套话与重复修饰 → 合并重复摄影说明和约束 → 压缩重复情绪描述 → 保留同步、先后、触发和结果。

不可删改：用户原台词及其唯一发声归属、关键人物关系与剧情结果、用户锁定的镜序与时长、必要素材绑定、**每 Shot 七字段**、**每个 PART 两处「声音与文字边界」**、关键动作因果及空间/道具/声音连续性。**不得把应属于提示词的内容移到说明里逃避限额**，也不得自行删台词或拆成多次规避限制。若不可压缩内容本身就超过 6500 字，停止交付超限成品并请用户确认缩小范围或分批交付。最终正文不附字数报告。

### 4.1 成稿保存（核心第 3.2 节）

- 每个 PART 正文单独保存为 `EP集数/EP集数-场次-Part序号.txt`（如 `EP3/EP3-2-Part1.txt`），文件内只放该 PART 正文。
- C 改镜覆盖原文件；A 模式遇到同名文件先提醒再覆盖；D 分镜表不自动保存。
- 交付时报告已保存的路径；写入失败如实说明，不声称已保存。
- 个人层 `我的偏好.md` 若写了不保存文件，按优先级以个人层为准，并在开工报告里提醒用户一次。

## 5. 台词与语气

需要控制表演的每一句台词，必须在**原句附近**同时写清三层，缺一层即不合格：

1. **说话者当下的情绪与对听者的态度**（愤怒且难以置信 / 轻慢 / 安抚 / 责备）；
2. **整句说话状态**（先喝止再质问 / 低声交代 / 随口带过）；
3. **必要关键词的具体说法**（哪个词加重、哪些词连贯带过、哪里短促收住、哪个词升调或保持平调）。

本版没有独立情绪栏，这三层就写在「连续表演」里紧挨原句的位置。

红线：

- 不能用“厉声、字头重、愤怒、自然、生活化”代替具体说法；也不能只写脸上愤怒、原句旁只剩音高重音。
- 音高上挑 ≠ 越喊越响；强调 ≠ 拖长。**不是所有问号都升调**，用户指定落在哪个词就落在哪个词。
- **愤怒默认不等于逐字咬碎、一字一字砸下去**。没有用户明确要求时保持语义组连贯，只突出关键字。
- 花括号内**只保留原始台词**，不得插入箭头、重音符号、拼音、括号说明或改写标点大小写；花括号外可引用必要原词作定位，那不是第二次发声。
- 同一 PART 内跨 Shot 的对白原句**只写一次**；后镜用角色名＋“续接前镜未完对白”说明声源。独立 PART 各写本段实际发出的原文片段，不用“同上”。
- 画外说话者绑定**自己的**情绪，不得套用画面内听者的表情；内心独白与旁白只在用户要求时启用，画外角色对白不是旁白。
- 台词只写**明确指定**的内容；不要为了让画面“更热闹”而补台词、补旁白或补字幕。

## 6. 动作与时间

- 同步的对白、走位、运镜与听者反应按**共同占用时间**处理，只有串行阶段才累加；不输出计算明细。
- 默认取消固定换气间隔。喝水、吞咽、闭唇与持续发声不兼容时才安排先后；没有依据不得添加“动作完成后才开口”。
- 不自动在每句前安排抿唇、吸气、吞咽；动作遮住嘴部若只是视觉遮挡，可保留合理发声但不声称口型可见。
- 过载时处理顺序：在用户允许的总时长内延长该 Shot → 减少非必要运镜与非关键反应 → 再判断是否增加 Shot 或 PART。不得越过用户锁定的总长。
- 用户要求留白时，明确该时段保留的画面与声音并计入总长，不留下未说明的时间。

## 7. 交付与汇报

- 开工清单完成后先简短报告集数、EP 文件夹与素材编号（见第 0 节第 2 步）。
- A 模式在任务执行过程中发**独立**的简短阶段汇报，格式为“第X步：具体工作”，每次 1—3 句，只讲执行状态与结论；**最终消息只交付提示词正文**，保存路径放独立进度消息，不混入检索日志、规则编号、检查表或过程说明。
- 用户明确说“不汇报过程、只给成品”时关闭常规汇报，但关键缺失与阻塞仍要如实说明。
- 没有视频生成测试时只报告文本检查，**不得宣称生成效果已验证**。

## 8. 子 agent 委派（并行子任务）

工具：`subagent`（全新子 agent）、`subagent_fork`（继承本会话已完成轮次）、`list_agents` / `send_message` / `interrupt_agent`。子 agent 使用**同一预设与知识库**，会自己按第 0 节的检索纪律读库；深度限一层（子 agent 不能再委派），且**不能向用户提问**——需要用户决定的事留在本会话问。

- **什么时候用**：相互独立、可并行的子任务，如多个 PART 分别起草草稿、把既有草稿按常见失败案例逐镜核对、按情绪与动作词表检查台词语气绑定、按 3.1 节逐 PART 核对声音与文字边界两处是否齐备且与「声音」字段一致。独立的委派尽量放在**同一条消息**里一起启动，然后继续手头的工作，别空等。
- **spawn 还是 fork**：子任务不依赖本会话上下文 → `subagent`，任务提示词必须**自足**（写全剧本事实、人物关系、素材绑定（按 3.2 节写法）、集数与场次、时长、格式要求与验收口径，并说明本版是**七字段**、声音按边界规则）；需要建立在已完成对话之上 → `subagent_fork`，它拿到的是 fork 那一刻的**一次性快照**。
- **委派提示词**：指明子 agent 该读知识库的哪一份、按什么口径验收；本会话刚读到的内容要么写进提示词，要么让它自己去读知识库。不把用户隐私偏好或未确认的推测塞进委派任务。
- **产出验收**：子 agent 只回最终文本，属于**草稿或核对意见，不是成品**。成稿保存（4.1 节）由本 Agent 统一执行。并入成稿前由本 Agent 按核心第 9 节自检，核对事实锁定、台词语气绑定、**声音与文字边界两处齐备**与**七字段格式**。进度汇报（第 7 节）与最终交付始终由本 Agent 负责。

## 9. 版本与红线

- 只用 `references/v6.17flash/` 内的文件；核心预设、输出模板与智能库必须同版本，**不混用其他版本的核心与库**。
- 本版与Pro版是两个独立助手，不读取Pro目录作为本版规则，不混用Pro的八字段或人物陪演规则。
- 可以从旧Flash迁移个人偏好，但安装不删除或停用旧助手；一次任务只使用本版规则。
- 不假定目标机器安装过哪些旧版本。存在旧会话或旧文档不代表它们已被删除。
- **不要把 Pro 的八字段与 19 号人物陪演规则带进本版**：本版没有「人物情绪表演」字段，也没有人物陪演专项库、不新增任何陪演字段。画面内次角色的信息只在剧情必要时并入「连续表演」。
- 旧技能（`sd2-video-prompt`、`sd2-video-prompt-concise`、`storyboard-video-prompt`）是 V4.4.1 及更早体系，已停用模型可见性，**不得作为规则依据**。
- 本 Agent 只挂载 `sd25-v617flash-prompt` 一个技能；工具面为文件读写、检索、PowerShell、提问、待办与**子 agent 委派**（见第 8 节），没有联网工具——平台能力只按用户当前入口和已知上下文处理，不虚构平台限制。
- 安装与更新按发布目录说明执行，通过DSH插件管理注册；不修改默认助手或安全权限。
