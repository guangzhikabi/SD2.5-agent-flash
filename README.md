# SD2.5 提示词助手 V6.17Flash[cite: 1]

**把剧本变成有镜头、有表演、有声音与连续性的 Seedance 视频提示词。**[cite: 1]

不只写“电影感、情绪强烈、镜头推进”，而是进一步说明：摄影机在哪里、人物怎样动、台词怎么说、动作与对白如何同步，以及这一镜结束后留下什么状态[cite: 1]。

这是运行在 **DeepSeek Harness（DSH）** 中的可选助手预设插件，包含核心规则、输出模板、7 份知识库和完整样例[cite: 1]。安装后，在 DSH 新会话中选择本助手，即可通过对话完成剧本转写、分镜讨论、局部改镜和分镜表制作[cite: 1]。

> **使用说明**：本助手负责编写提示词，不直接生成视频，也不提供视频生成额度或自动调用视频平台[cite: 1]。生成的成稿需要你手动提交到支持相应提示词与素材参考的视频生成平台[cite: 1]。安装本插件不会自动切换你的默认助手，也不会替换其他助手[cite: 1]。

## 它是什么？

你可以把它理解为一个带有固定工作方法和参考库的 **AI 分镜顾问**[cite: 1]：

- **剧本转提示词**：输入剧本、场次说明、大纲或已有分镜，帮你组织成可直接使用的视频提示词[cite: 1]。
- **前期分镜讨论**：不确定镜头应该怎样设计时，先帮你分析不同方案的选择与代价，不急着直接输出成品[cite: 1]。
- **先出表再展开**：想先确认分镜再生成提示词时，先输出标准九列分镜表，等你确认无误后再展开写成稿[cite: 1]。
- **精准局部改镜**：已有成稿只想修改其中一镜时，自动检查前后镜头的承接关系，不会把整段无关内容推翻重写[cite: 1]。

*(注：本插件不是视频生成模型、剪辑软件或独立聊天客户端；需要在 DSH 中配合你已配置的对话模型使用，模型的理解、文件操作和指令遵循能力会影响实际表现[cite: 1]。)*

## 核心优势

普通提示词容易只写出“氛围”，却没有交代清楚具体的执行关系[cite: 1]。本助手专门针对以下容易反复返工的痛点进行了规则设计[cite: 1]：

| 常见痛点问题 | 本助手的处理方式 | 对使用者的实际帮助 |
| :--- | :--- | :--- |
| **镜头描述只有“电影感、特写、慢推”** | 分开说明机位、可见范围、画面焦点、受光与主要运镜[cite: 1] | 更容易检查镜头想表达什么，而不是堆砌摄影术语[cite: 1] |
| **动作和台词像两套独立流程** | 将表演、动作、对白和反应写入同一个“连续表演”事件，区分同步、先后与打断[cite: 1] | 减少“说完才动、动完才说”的机械木偶感编排[cite: 1] |
| **台词被改写，或切镜后又重说一遍** | 严格保留用户原句并指定唯一发声者，跨镜说明续接，不重新起句[cite: 1] | 高度契合需要忠实还原剧本台词的任务[cite: 1] |
| **切镜后站位、道具、动作状态全变了** | 自动继承人物身份、位置、道具持有和动作相位，镜尾强制记录影响下一镜的状态[cite: 1] | 方便直观检查前后镜头是否严丝合缝地衔接[cite: 1] |
| **只写“愤怒地说”，缺乏具体表演** | 把抽象情绪落实为当前景别下可见、可听的动作质感与说话方式[cite: 1] | 让表演要求具体可执行，告别空洞的情绪标签[cite: 1] |
| **一段提示词越写越长，超出限制** | 按所有 PART 合计 6500 Unicode 字符的上限组织与压缩，优先保护台词、剧情和必要字段[cite: 1] | 提供明确的精简优先级，绝不靠删减剧情来凑字数[cite: 1] |
| **想改一点，却牵动了整段内容** | 局部修改后，专门复核上下镜的时间、站位、道具、声音和情绪承接[cite: 1] | 避免“只改局部、却在后续镜头留下穿帮矛盾”的情况[cite: 1] |

### ⚡ V6.17Flash 的“精简”体现在哪里？

在生成正式提示词（A 模式）时，每个镜头固定保留 **7 个核心标题**[cite: 1]：

> **景别/机位 → 画面层次与焦点 → 光线与受光 → 运镜 → 连续表演 → 声音 → 结束状态**[cite: 1]

- **合并同类项**：将人物情绪、动作质感、发声方式、完整台词与必要的听者反应，统一整合在 **“连续表演”** 字段中，不再单独设立“人物情绪表演”栏[cite: 1]。这样可以把同一件事写在一起，大幅减少分栏造成的重复赘述[cite: 1]。
- **不减核心质量**：Flash 精简的只是字段组织形式，**绝不会把台词、动作因果和镜头连续性省掉**[cite: 1]。

## 四大工作模式

日常使用时**不需要背诵模式字母**，直接用自然语言告诉助手你的需求即可[cite: 1]：

| 模式 | 适用场景与日常说法示例 | 助手的交付方式 |
| :--- | :--- | :--- |
| **A：提示词模式** | “把这场戏直接转成提示词”[cite: 1] | 按主模板输出完整的多镜头 PART 提示词并保存[cite: 1] |
| **B：商量／审查模式** | “这段节奏为什么不顺？”、“这里用固定镜还是手持更合适？”[cite: 1] | 分析问题原因、不同方案的选择与代价，不强行输出成稿[cite: 1] |
| **C：局部改镜模式** | “只改第二镜，其他已确认内容不动”[cite: 1] | 仅修改受影响的镜头内容，同步检查前后镜承接并更新文件[cite: 1] |
| **D：分镜表模式** | “先给我出分镜表，等我确认后再展开写提示词”[cite: 1] | 输出固定九列分镜表；按要求停下等待确认，确认后再转成提示词[cite: 1] |

## 快速开始

### 1. 安装到 DSH
1. 下载本仓库 ZIP 或 Release 压缩包，**先完整解压到本地固定目录**[cite: 1]。
2. 在 DSH 中打开该解压目录，直接对具备插件管理权限的 AI 发送以下话术，让其读取 [给AI的安装指令](给AI的安装指令.md) 自动完成安装[cite: 1]：

```text
请读取当前目录的《给AI的安装指令.md》，按说明安装 V6.17Flash。
只新增可选助手，不修改我当前的默认助手。
```

*(注：完整安装包含“准备资产”和“DSH 插件管理注册”两步，仅运行完准备程序还不算安装完成，需等待 AI 完成插件注册汇报[cite: 1]。)*

### 2. 开启新会话并选择助手
安装完成后，根据 DSH 提示决定是否重启客户端[cite: 1]。随后**开启一个新会话**（已打开的旧会话不会自动切换助手），在预设列表中手动选择[cite: 1]：

👉 **`SD2.5提示词助手_V6.17Flash`**[cite: 1]

### 3. 准备文件并发起任务
建议在你的任务工作区放好剧本、说明文档以及需要用到的参考素材[cite: 1]。发指令时，尽量向助手交代清楚以下要素[cite: 1]：
- **集数与场次**：例如“第 3 集第 2 场”，便于助手确定文件归档位置[cite: 1]。
- **交付方式**：说明是直接成稿、先讨论方案、先看九列分镜表，还是局部改镜[cite: 1]。
- **时长与锁定要求**：例如“总长 15 秒”，以及必须保留的镜头顺序或关键动作结果[cite: 1]。
- **台词要求**：说明原始台词是否必须逐字保留[cite: 1]。
- **素材用途**：指明工作区里哪个文件对应哪个角色、参考面部还是服装、哪段音频只取音色[cite: 1]。

*(不必担心一次没写全所有细节：凡是影响剧情或素材对应的关键缺口，助手会主动先向你提问确认；不改变剧情的普通执行细节，助手会按规则做最小化合理补全[cite: 1]。)*

## 使用示例（可直接复制套用）

### 示例一：直接把剧本转成提示词（无外部素材）
```text
第3集第2场，总时长15秒，直接输出提示词。

办公室里，林舟站在桌旁，把信封放到桌上，压低声音说：
“合同我看过了。”
许宁坐在桌后，没有接信封，只抬眼看他。

台词逐字保留，不增加对白，不改变动作结果。
工作区没有参考图片和音频，以文字设定为准。
```
> **执行逻辑**：助手会先确认任务工作区与集文件夹，按七字段模板组织镜头，核对台词、时长和动作关系，最后按规则保存成稿（无外部素材时绝不虚构图片或音频编号）[cite: 1]。

### 示例二：先看九列分镜表，确认后再展开
**第一步（发任务要分镜）：**
```text
把这场戏先做成九列分镜表，等我确认后再写提示词。
总时长20秒，保留全部台词，不新增人物。
```
**第二步（确认分镜后要求成稿）：**
```text
按刚才确认的镜序、台词和时长展开成提示词，不改变剧情。
```

### 示例三：只修改其中一镜（局部返修）
```text
只改第二镜：把慢推改为固定镜，人物动作和台词不变。
检查与第一、第三镜的站位、道具持有和声音承接。
其他已确认内容不要重写。
```

### 示例四：绑定人物图、场景图与音色参考
```text
工作区的“林舟 西装.png”对应林舟，只参考面部与服装；
“办公室.png”作为场景参考；
“林舟 音色.wav”只参考林舟的声音音色。
默认不打开图片和音频，不从文件名猜外貌。
按本次实际上传顺序给素材编号，先汇报绑定关系再成稿。
```
> **生成的绑定格式示意**：
> ```text
> 图1@办公室 绑定为办公室场景参考。
> 图2@林舟 西装 绑定为林舟，面部与服装参考。
> 将音频1@林舟 音色 绑定为林舟的声音音色，只取音色，不继承原台词、背景音乐与背景声。
> ```
> **⚠️ 重要提醒**：助手写出绑定语句不等于自动帮你把素材传到了视频平台[cite: 1]。实际生成视频时，你仍需在视频平台手动上传对应文件，并确保**上传顺序与提示词里的编号（图1、图2、音频1）严格一致**[cite: 1]。

## 工作区与保存规则

### 1. 素材处理：默认只认文件名，不擅自看图听音
- **扫描机制**：助手开工时会扫描任务工作区，自动识别剧本文档以及图片、音频、视频文件[cite: 1]。
- **隐私与准确性**：剧本文档和说明文档会正常读取；但**图片、音频、视频默认绝不自动打开**（只有当你明确下令要求查看某个媒体文件时才会打开）[cite: 1]。人物外貌特征严格依据剧本、你的说明或已确认的绑定信息编写，绝不凭文件名看字生义、盲目编造[cite: 1]。

### 2. 声音与文字边界：保留真实同期声，杜绝乱加配乐字幕
- **默认保留项**：角色对白、符合当前场景的自然环境底声、有明确动作来源的真实拟音（以及剧情内真实的道具文字、场景内画外角色对白）[cite: 1]。
- **默认禁止项**：默认不加 BGM、配乐、转场音效、情绪强调音或无来源装饰音；默认不自动添加旁白、对白字幕和人物姓名标签[cite: 1]。
- **灵活覆盖**：如果你在某场戏中明确要求加入音乐、字幕、旁白或全静音，助手会按你的要求同步调整允许与禁止范围[cite: 1]。

### 3. 自动归档保存：按“集 / 场次 / PART”规范存放
A 模式（正式成稿）与 C 模式（局部改镜）默认按以下目录结构自动保存，每个独立 PART 单独存为一个 `.txt` 文件（D 模式分镜表默认不自动保存文件）[cite: 1]：

```text
任务工作区/
└─ EP3/
   ├─ EP3-2-Part1.txt
   └─ EP3-2-Part2.txt
```
- 集数或场次不明确时，助手会先向你询问；工作区已有集文件夹（如 `EP3`）时会直接沿用原命名写法，不会擅自补零改成 `EP03`[cite: 1]。
- A 模式遇到同名文件会先提醒你确认，C 模式改镜会直接更新对应文件，绝不擅自删除工作区内的其他项目文件[cite: 1]。

### 4. 个人偏好设置：记住你的长期习惯
个人偏好与核心知识库独立存放，你可以将自己的长期习惯写入个人偏好中[cite: 1]：
- 常用的单段目标时长、画面风格偏好与汇报习惯[cite: 1]。
- 是否默认每次都先做九列分镜表[cite: 1]。
- 是否开启自动保存、项目中的固定角色/场景名称与素材编号习惯[cite: 1]。

> **生效优先级**：`你当次对话的明确要求` ＞ `个人偏好设置` ＞ `系统默认偏好`[cite: 1]。新安装时默认使用纯净模板（不带发布者的私人习惯）；版本更新时会原样保留你已有的个人偏好设置[cite: 1]。

## 内置知识库

本插件内置 7 份核心专业知识库（配合核心预设、唯一输出模板与完整样例使用），助手在运行时会根据当前任务按需检索，无需每次全量读取[cite: 1]：

| 文件编号 | 知识库名称 | 主要用途说明 |
| :---: | :--- | :--- |
| **01** | **规则与参数** | 定义输出格式、参数限制、内部规则条目与不可逾越的红线[cite: 1] |
| **13** | **镜头卡样本库** | 提供单镜头的标准组织骨架参考[cite: 1] |
| **14** | **场景原型与镜组套路** | 根据具体空间与戏剧事件，匹配合适的镜头组合套路[cite: 1] |
| **15** | **情绪与动作词表** | 将抽象的情绪、动作和说话方式，转化为画面可见、声音可听的具体描述[cite: 1] |
| **16** | **常见失败案例库** | 针对视频生成中的高频翻车风险进行定位、排查与核对[cite: 1] |
| **17** | **机位轴线与对话机制** | 规范视点选择、人物空间关系与多人对话调度，防止越轴混乱[cite: 1] |
| **18** | **运镜光线与转场机制** | 指导摄影机运动、光线受光承接及镜头转场方式的选择[cite: 1] |

*(注：本版本为 **V6.17Flash**，不包含 Pro 版的独立人物情绪栏或人物陪演专项库，请勿混用其他版本规则[cite: 1]。包内完整保留 13 份原始 Markdown 文档及检索索引[cite: 1]。)*

## 安装与更新指南（管理员与技术参考）

普通用户直接按上文 [快速开始](#1-安装到-dsh) 让 DSH 里的 AI 读取 [给AI的安装指令](给AI的安装指令.md) 即可完成操作[cite: 1]。以下为底层安装机制与更新边界，供自行维护环境的使用者参考[cite: 1]：

1. **运行环境要求**：
   - 宿主环境需为具备 `agent-preset`、`persona`、文件、检索、技能及相关内置工具插件的 DSH，并由使用者自行配置好可用的对话模型[cite: 1]。
   - `Node.js 18+` 仅在首次安装或更新的“一次性资产准备阶段”使用，日常成稿与计数不会调用外部脚本或进程[cite: 1]。
2. **资产准备命令**：
   - 在解压目录下运行 `node 安装准备.mjs --apply` 执行实际写入（若不带 `--apply` 参数则仅作只读预览）[cite: 1]。
   - 若目标环境已安装过本版本，在取得更新确认后需加上 `--update` 参数运行[cite: 1]。
3. **目标目录规则**：
   - 默认读取环境变量 `DSH_HOME`，若未设置则使用当前系统用户目录下的 `.dsh` 文件夹[cite: 1]。
   - 多配置环境或便携版部署，请使用 `--home` 参数显式指定目标数据目录[cite: 1]。
4. **插件注册流程**：
   - 资产准备完成后，由 DSH 的 `plugin_manager` 注册准备程序返回的 `bundle` 目录，并检查 `application` 状态、诊断信息与重启要求[cite: 1]。
   - **切勿直接注册尚未经过准备程序替换路径占位符的原始下载文件夹**[cite: 1]。
5. **版本更新与旧版迁移**：
   - **同版本更新**：自动保留个人偏好与用户自建文件，并在覆盖前将旧目录完整备份至目标数据目录的 `_backups/sd25-v617flash/时间戳` 下[cite: 1]。
   - **从旧版迁移**：显式添加 `--update` 参数时，程序会按语义版本自动寻找旧版 Flash 的个人偏好进行迁移（自动排除 Pro 版、`.bak` 备份文件及未来版本）；普通全新安装则不会自动继承旧版偏好[cite: 1]。
6. **安全回退与卸载**：
   - 本插件在安装、更新或回退时，绝不直接写入修改用户的 `profile` 配置文件，不改写默认助手选择，也不删除其他助手或项目文件[cite: 1]。
   - 若需回退版本，请先通过 DSH 插件管理器禁用或注销本 bundle，随后恢复 `_backups` 中的备份文件并重新注册原版本[cite: 1]。卸载插件不会自动删除你的个人偏好与历史备份[cite: 1]。

### 📌 版本与使用边界说明
- **当前版本**：助手内核版本 **V6.17Flash** ｜ 插件分发包版本 **1.0.1**（核心规则、模板和知识库原文保持不变；分发层已适配便携路径，并取消了技能入口中强制调用外部计数命令的要求）[cite: 1]。
- **字符数上限**：单次交付的所有 PART 合计上限为 **6500 Unicode 字符**（含空格与换行）[cite: 1]。当宿主环境没有无需额外授权的精确计数工具时，助手会自动预留明显余量，不会虚报精确字数[cite: 1]。
- **生成效果说明**：本助手的规则旨在让提示词逻辑严密、连续无歧义，但提示词本身无法保证视频生成端 100% 精确命中时码、复杂动作、口型同步或绝对无字幕/无 BGM，关键镜头仍需结合实际视频生成结果进行测试与微调[cite: 1]。
