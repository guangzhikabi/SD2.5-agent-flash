# SD2.5 提示词助手 V6.17Flash

**把剧本变成有镜头、有表演、有声音与连续性的 Seedance 视频提示词。**

不只写“电影感、情绪强烈、镜头推进”，而是进一步说明：摄影机在哪里、人物怎样动、台词怎么说、动作与对白如何同步，以及这一镜结束后留下什么状态。

这是运行在 **DeepSeek Harness（DSH）** 中的可选助手预设插件，包含核心规则、输出模板、7份知识库和完整样例。安装后，在 DSH 新会话中选择本助手，即可通过对话完成剧本转写、分镜讨论、局部改镜和分镜表制作。

> **它负责写提示词，不直接生成视频。** 成稿需要你提交到支持相应提示词与素材参考的视频生成平台。安装不自动切换默认助手，也不替换其他助手。

[快速开始](#快速开始) · [使用示例](#使用示例) · [为什么好用](#为什么好用) · [安装与更新](#安装与更新)

## 它是什么？

你可以把它理解为一个带有固定工作方法和参考库的 **AI分镜顾问**：

- 输入剧本、场次说明、大纲或已有分镜，它帮助组织成可使用的视频提示词。
- 不确定镜头应该怎样设计时，先讨论选择与代价，不急着输出成品。
- 已有结果只想修改一镜时，检查相关承接，不把整段无关内容全部重写。
- 想先确认分镜再生成提示词时，先出九列表格，等你确认后再展开。

它不是视频模型、剪辑软件或独立聊天客户端；需要在 DSH 中使用你已配置的对话模型。模型的理解、文件操作和指令遵循能力，会影响实际表现。

## 为什么好用？

普通提示词容易写出“氛围”，却没有交代清楚执行关系。本助手把注意力放在下面这些容易反复返工的问题上。

| 常见问题 | 本助手怎样处理 | 对使用者的帮助 |
| --- | --- | --- |
| 镜头描述只有“电影感、特写、慢推” | 分开说明机位、可见范围、画面焦点、受光与主要运镜 | 更容易检查镜头想表达什么，而不是堆术语 |
| 动作和台词像两套独立流程 | 将表演、动作、对白和反应写入同一个连续事件，区分同步、先后与打断 | 减少“说完才动、动完才说”的机械编排 |
| 台词被改写，或切镜后又说一遍 | 保留用户原句和唯一发声者，跨镜说明续接，不重新起句 | 适合需要忠实转写剧本的任务 |
| 切镜后站位、道具、动作状态变了 | 继承身份、位置、道具持有和动作相位，镜尾记录影响下一镜的状态 | 便于检查前后镜是否衔接 |
| 只写“愤怒地说”，没有具体表演 | 把情绪落实为当前景别可见、可听的动作质感与说话方式 | 让表演要求更具体，而不是只有标签 |
| 一段提示词越写越长 | 按所有PART合计6500字符的限制组织与压缩，优先保护台词、剧情和必要字段 | 给精简提供明确顺序，不靠删剧情凑长度 |
| 想改一点，却牵动了整段 | 局部修改后复核上下镜的时间、站位、道具、声音和情绪 | 减少只改局部、留下后续矛盾的情况 |

这些是规则与工作流程上的设计目标，**不代表视频生成端必然精确执行，也不是经过统一基准测试的成功率承诺**。

### Flash 的“精简”体现在哪里？

A模式每镜保留七个标题：

**景别/机位 → 画面层次与焦点 → 光线与受光 → 运镜 → 连续表演 → 声音 → 结束状态**

人物情绪、动作质感、发声方式、完整台词与必要听者反应，统一放在“连续表演”中，不另设“人物情绪表演”栏。这样可以把同一件事写在一起，减少分栏造成的重复。

Flash精简的是字段组织，**不是把台词、动作因果和连续性省掉**；也不意味着在所有模型上都一定更快或更省费用。

## 可以用它做什么？

| 模式 | 适合的需求 | 交付方式 |
| --- | --- | --- |
| A：提示词 | “把这场戏转成提示词” | 按主模板输出多镜头提示词 |
| B：商量／审查 | “这段为什么不顺？”“固定镜还是手持更合适？” | 解释问题、选择与代价，不强行成稿 |
| C：改镜 | “只改第二镜，其他已确认内容不动” | 修改受影响内容，并检查前后镜承接 |
| D：分镜表 | “先给我分镜，确认后再展开” | 固定九列分镜表；按要求等待确认或继续转成提示词 |

不需要记住模式字母，用自然语言说明需求即可。

## 快速开始

### 1. 安装到 DSH

下载本仓库 ZIP，或下载 Release 压缩包，**先解压到固定目录**。在 DSH 中打开该目录，让具备插件管理权限的助手读取 [给AI的安装指令](给AI的安装指令.md)。可以直接说：

```text
请读取当前目录的《给AI的安装指令.md》，按说明安装 V6.17Flash。
只新增可选助手，不修改我当前的默认助手。
```

安装包含“准备资产”和“DSH插件管理注册”两步，只有准备程序运行成功，还不算安装完成。安装所需权限由DSH管理，本包不绕过授权。

### 2. 开新会话，选择本助手

安装完成后，按DSH提示决定是否需要重启。开启新会话，手动选择：

**SD2.5提示词助手_V6.17Flash**

本包不会把它自动设为默认助手；已经打开的会话也不会自动换人格。

### 3. 准备剧本与素材，直接说明需求

建议在任务工作区放好剧本、说明文档和要使用的参考素材。开始时尽量告诉助手：

- **哪一集、哪一场**：便于确定保存位置。
- **要做什么**：直接成稿、先讨论、先分镜，还是局部修改。
- **时长与已锁定要求**：例如总长15秒、必须保留的镜序或动作结果。
- **原始台词**：说明是否必须逐字保留。
- **素材用途**：哪个文件对应谁、参考面部还是服装、哪个音频只取音色。

不必一次填满所有细节。影响剧情或素材对应的关键缺口，助手应先询问；不改变剧情的普通执行细节，可以按规则最小补全。

## 使用示例

### 示例一：直接把剧本转成提示词

```text
第3集第2场，总时长15秒，直接输出提示词。

办公室里，林舟站在桌旁，把信封放到桌上，压低声音说：
“合同我看过了。”
许宁坐在桌后，没有接信封，只抬眼看他。

台词逐字保留，不增加对白，不改变动作结果。
工作区没有参考图片和音频，以文字设定为准。
```

助手应先确认任务工作区与集文件夹，按本版七字段组织镜头，核对台词、时长和动作关系，再按规则保存成稿。没有外部参考素材时，不应虚构图片或音频编号。

### 示例二：先确认分镜，再展开

```text
把这场戏先做成九列分镜表，等我确认后再写提示词。
总时长20秒，保留全部台词，不新增人物。
```

确认分镜后，再说：

```text
按刚才确认的镜序、台词和时长展开成提示词，不改变剧情。
```

### 示例三：只修改一镜

```text
只改第二镜：把慢推改为固定镜，人物动作和台词不变。
检查与第一、第三镜的站位、道具持有和声音承接。
其他已确认内容不要重写。
```

### 示例四：绑定图片与音色

```text
工作区的“林舟 西装.png”对应林舟，只参考面部与服装；
“办公室.png”作为场景参考；
“林舟 音色.wav”只参考林舟的声音音色。
默认不打开图片和音频，不从文件名猜外貌。
按本次实际上传顺序给素材编号，先汇报绑定关系再成稿。
```

绑定格式类似：

```text
图1@办公室 绑定为办公室场景参考。
图2@林舟 西装 绑定为林舟，面部与服装参考。
将音频1@林舟 音色 绑定为林舟的声音音色，只取音色，不继承原台词、背景音乐与背景声。
```

这里的文件名和编号仅为示意。**写出绑定句不等于把素材上传到视频平台**：实际使用时，你仍需上传对应素材，并确认提示词编号与平台中的上传顺序一致。

## 素材、声音与保存怎样处理？

### 素材：默认只识别文件名，不擅自看图或听音频

助手开工时扫描任务工作区，识别图片、音频、视频及剧本文档。图片、音频、视频默认不打开；只有你明确要求查看某个文件时才打开。剧本和说明文档可正常读取。

外貌特征来自剧本、你的说明或已确认绑定，不能只凭文件名编造。角色对应或素材用途不明确时，应先确认。

### 声音：不是默认静音，也不是自动配乐

默认保留对白、符合场景的自然环境音与真实动作拟音；默认不增加BGM、配乐、转场音、情绪强调音或无来源装饰音，也不自动添加旁白、对白字幕和姓名标签。

你明确要求音乐、字幕、旁白或静音时，可按要求调整相应默认项。剧情中的真实道具文字与场景内画外角色对白，不应被误当成禁项。

### 保存：按集、场次与PART组织

A成稿、C改镜默认按下面的结构保存，每个PART单独一个文件：

```text
任务工作区/
└─ EP3/
   ├─ EP3-2-Part1.txt
   └─ EP3-2-Part2.txt
```

集数或场次不明确时先询问；已有集文件夹沿用原写法，不自行补零。A模式遇到同名成稿先提醒，C模式改镜更新对应文件；不删除其他项目文件。D分镜表不自动保存。

如果个人偏好关闭了保存，则按偏好处理并提醒；没有文件写入能力时，如实说明未保存。示意中有两个PART，不代表每个任务都要拆成两段。

## 能不能设置自己的习惯？

可以。个人偏好与核心知识库分开存放，例如：

- 常用时长、画面风格和汇报习惯。
- 是否需要先做分镜表。
- 是否保存成稿、项目中的固定名称与素材编号习惯。

优先级是：**你当前的明确要求 ＞ 个人偏好 ＞ 体系默认偏好**，同时遵守宿主与生成平台的实际能力边界。

新安装使用全默认个人层，不带发布者的私人习惯。更新时保留你原有偏好的字节内容，不强行把旧设置改成新默认。

## 安装与更新

普通使用者从 [给AI的安装指令](给AI的安装指令.md) 开始即可。下面是安装机制与更新边界，供管理安装的使用者参考。

- **环境**：具备agent-preset、persona、文件、检索、技能及相关内置工具插件的DSH；使用者自行配置对话模型。Node.js 18+仅用于一次性安装准备。
- **准备资产**：运行 `node 安装准备.mjs --apply`。不带 `--apply` 为只读预览；目标已有本版时，取得更新同意后加 `--update`。
- **目标目录**：默认采用 `DSH_HOME`，否则使用当前用户的 `.dsh`；多配置或便携部署应显式指定 `--home`。
- **注册插件**：由DSH的 `plugin_manager` 注册准备程序返回的bundle目录，检查 `application`、诊断与重启要求；不要直接注册尚未替换路径占位符的下载资产。
- **更新本版**：保留偏好与用户自建文件，先完整备份旧目录至目标数据目录的 `_backups/sd25-v617flash/时间戳`。
- **从旧版迁移**：显式 `--update` 时，按语义版本寻找旧Flash偏好，排除Pro、`.bak`及未来版本；普通新装不自动继承旧版偏好。
- **不改默认选择**：不写profile，不调用默认助手设置，不删除旧版、其他助手或项目。

本包采用 **资产准备 + DSH标准bundle注册**，不是向任意插件入口上传ZIP就一定能用的单文件插件。注册可能需要联网，兼容性与所需权限由DSH版本、配置和宿主策略决定。

注册失败时不得宣称安装成功。回退应通过DSH插件管理禁用或注销本bundle，再恢复备份并注册原版本，不直接手改profile。卸载不自动删除个人偏好与备份。

## 使用边界与验证范围

- 不为成稿核对或计数启动外部脚本、进程或要求扩大权限；只有安装准备阶段使用随包程序。
- 长度上限为一次交付所有PART合计6500 Unicode字符，含空格换行。没有无需额外授权的计数能力时留明显余量，不虚报精确字数。
- 提示词不能保证视频端精确命中时码、动作、口型、无字幕或无BGM。重要结果需要实际生成后检查。
- 本包不提供视频生成额度，也不自动替你上传素材或调用视频平台。
- 已完成本地静态检查和16项隔离安装准备／更新测试，涉及原文一致性、路径适配、偏好保留及默认配置不变；尚未在另一台机器完成实际DSH注册，也未进行视频效果测试。
